# Cohort & Unit Economics Engine (Retail / E-Commerce)

Аналитический инструмент на Python и SQLite для автоматической обработки выгрузок заказов, склейки профилей клиентов (Identity Resolution), когортного анализа, многоуровневой юнит-экономики и RFM-сегментации.

Проект решает проблему ручного сведения когорт в Excel/Google Таблицах: исключает человеческий фактор, устраняет дублирование профилей и сокращает время расчета с 40 минут до 0.34 секунды.

## 2. Склейка профилей клиентов (Identity Resolution)

В рознице и омниканальном екоме клиент оставляет телефон на кассе, email на сайте и случайный ID в мобильном приложении. В стандартных отчетах такой покупатель дробится на 2-3 разных человека, что искажает отток (Churn) и занижает реальный LTV.

Модуль `src/prepare.py` строит граф связей на непересекающихся множествах (алгоритм **Disjoint-Set / Union-Find**):
1. **Транзитивная склейка:** Ребра между всеми непустыми идентификаторами заказа (`cid:123`, `ph:+79991112233`, `em:user@mail.ru`). Если клиент оставил телефон на кассе, а затем тот же телефон и email на сайте, все его покупки объединяются в один профиль.
2. **Итеративный `find` (защита от RecursionError):** Реализация без рекурсии с двухпроходным сжатием пути выдерживает цепочки любой глубины (протестировано на 3 000+ связанных чеков).
3. **Защита от пустых ID:** Заказы без контактов изолируются персональными токенами `row:idx` и не склеивают независимых клиентов.

> [!IMPORTANT]
> **Ограничение и производственная практика (Стоп-лист технических контактов):** 
> Склейка идет по любому прямому совпадению. В реальном бизнесе массовые технические контакты (например, единый телефон кассира магазина или общий домен компании `@company.ru`) объединят тысячи чужих заказов в один профиль. В промышленном контуре такие аномальные номера и служебные email отсекаются стоп-листом (Blacklist) до этапа построения графа.

## 3. Формат входных данных

Инструмент принимает любой CSV-файл (разделители `;` или `,`, кодировки UTF-8 / UTF-8-SIG). Минимально необходимы поля даты, идентификатора и суммы.

### Пример входного CSV (`data/sample_orders.csv`):

```csv
order_id;order_date;client_id;phone;email;brand;channel;gross_revenue;cogs;delivery_cost;acquisition_cost;order_status
ORD-0000001;2025-01-10;CUST_00012;+79991112233;alex@example.com;UrbanStyle;online_site;6500.00;2730.00;350.00;1200.00;completed
ORD-0000002;2025-01-12;CUST_00045;+79992223344;;SportActive;offline_pos;8200.00;3936.00;0.00;1450.00;completed
ORD-0000003;2025-02-14;;+79991112233;alex@work.org;UrbanStyle;online_app;5900.00;2478.00;250.00;0.00;completed
ORD-0000004;2025-02-18;CUST_00099;;kate@domain.ru;SportActive;online_site;12400.00;5952.00;350.00;1100.00;completed
ORD-0000005;2025-03-01;CUST_00012;+79991112233;alex@example.com;UrbanStyle;offline_pos;7100.00;2982.00;0.00;0.00;completed
```

*(Заказы 1, 3 и 5 автоматически склеиваются в единого клиента `client_uid` по совпадению номера телефона).*

## 5. Методология юнит-экономики

- **Базовый LTV:** Выручка за весь срок жизни ($AOV \times Frequency \times Lifetime$).
- **Прямой LTV 1:** Валовая прибыль = Базовый LTV - Себестоимость товаров (COGS по принципу начисления).
- **Прямой LTV 2 (Вкладная маржа / Contribution Margin):** Прямой LTV 1 - Прямые переменные расходы (доставка, эквайринг, упаковка).
- **Чистый LTV:** Чистая прибыль бизнеса с клиента = Прямой LTV 2 - Стоимость привлечения (CAC).
- **Метрика окупаемости ($LTV / CAC$):** Отношение **Вкладной маржи (Прямой LTV 2)** к **CAC** (норматив $\ge 3.0$).

## 6. Быстрый старт

### Установка зависимостей
```bash
pip install -r requirements.txt
```

### Запуск полного пайплайна (на синтетике розницы)
```bash
python main.py
```

### Запуск на реальном датасете курса через SQL-движок (SQLite)
```bash
python main.py --input data/course/sheet_02_15phCO86.csv --sql --output output/report_course_02.md
```

### Запуск тестов (паритет SQL/Pandas + эталон Урока 3)
```bash
python -m unittest tests/test_pipeline.py
```
