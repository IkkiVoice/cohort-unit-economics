# Эпик: HTML-дашборд и локальный веб-интерфейс

ТЗ для агентной IDE. Проект `cohort-unit-economics`.

Декомпозировано на задачи. Каждую можно давать агенту отдельным промптом.

---

## Зачем

Сейчас отчёт выходит в markdown и читается только в редакторе. Нужны две вещи.

Первая: самодостаточный HTML-файл, который открывается двойным кликом и отправляется вложением. Один файл, без внешних зависимостей.

Вторая: локальный веб-интерфейс, куда файл кидается мышкой и возвращается готовый дашборд. Разворачивается на своей машине, как Redmine.

Ядро расчётов не трогается. Всё новое живёт в отдельных модулях поверх существующего пайплайна.

---

## Дизайн-система

Ориентир: интерфейсы Mindbox. Много воздуха, минимум декора, акцент только на цифрах.

**Палитра**

```
--bg:        #F7F8FA   фон страницы
--surface:   #FFFFFF   карточки
--border:    #E8EAEF   разделители
--text:      #16182B   основной текст
--text-dim:  #6B7280   подписи и пояснения
--accent:    #4A3AFF   акцент, ссылки, активные элементы
--positive:  #00B856   рост, здоровые метрики
--warning:   #F5A623   предупреждения
--negative:  #E5484D   падение, проблемы
--heat-0:    #F7F8FA   тепловая карта, минимум
--heat-100:  #4A3AFF   тепловая карта, максимум
```

**Типографика**

Системный стек: `-apple-system, "Segoe UI", Roboto, Inter, sans-serif`.

Цифры табличные: `font-variant-numeric: tabular-nums`. Без этого колонки прыгают.

Размеры: заголовок раздела 20px/600, крупная цифра в карточке 32px/600, тело 14px/400, подпись 13px/400 цветом `--text-dim`.

**Карточки**

Радиус 12px, фон `--surface`, граница 1px `--border`, без теней или тень еле заметная. Внутренний отступ 20px.

**Правило**

Никаких градиентов на фонах, никаких иконок ради иконок, никаких анимаций кроме появления графиков.

## E1. Генератор HTML-отчёта

### T1.1 Каркас и стили

Создать `src/report_html.py`. Функция принимает те же данные, что и `report.py`, возвращает строку HTML.

Один файл на выходе. CSS инлайн в теге `style`, никаких внешних ссылок на шрифты и библиотеки.

Ширина контента 1100px по центру, на экране уже 900px карточки перестраиваются в одну колонку.

Шапка: название отчёта, имя исходного файла, число строк, движок расчёта, дата.

**Приёмка:** файл открывается в браузере без интернета, выглядит одинаково в Chrome и Firefox.

### T1.2 Блок полноты данных

Первый блок после шапки. В режиме `partial` выводится плашка цветом `--warning` с текстом, каких данных нет и какие блоки не рассчитаны.

В режиме `full` плашка не выводится вовсе.

Под плашкой таблица полей: название, есть или нет, влияние на расчёт.

**Приёмка:** на курсовом файле плашка есть, на синтетике её нет.

### T1.3 KPI-карточки

Ряд из четырёх карточек. Mindbox выводит на главную четыре ключевых показателя, придерживаемся того же.

Состав в полном режиме: базовый LTV, чистый LTV, CAC, отношение LTV к CAC.

Состав в частичном: базовый LTV, средний чек, частота покупок, срок жизни.

В каждой карточке: подпись сверху цветом `--text-dim`, крупная цифра, под ней однострочное пояснение простым языком.

Для отношения LTV к CAC цветовая индикация: от 3 зелёный, от 2 оранжевый, ниже красный.

**Приёмка:** карточки не показывают ноль там, где значение `None`. Вместо цифры прочерк и пояснение, каких данных не хватает.

### T1.4 Тепловая карта удержания

Таблица когорта на период, M0 по M8.

Заливка ячейки пропорциональна доле удержания: чем выше, тем ближе к `--heat-100`. Текст в тёмных ячейках белый.

Ячейки ненаступивших периодов не заливаются и содержат прочерк.

В ячейке два значения: процент крупно, абсолютное число мельче под ним.

Под таблицей строка средних по столбцам и строка с числом когорт в расчёте.

**Приёмка:** у последней когорты залиты только доступные периоды. Средние совпадают с markdown-отчётом.

### T1.5 Графики

Chart.js встраивается в файл целиком, не ссылкой на CDN. Иначе отчёт перестанет работать без интернета.

Три графика.

Кривая удержания: по оси X период, по Y средний процент удержания. Одна линия.

Столбцы выручки по когортам: суммарная выручка каждой когорты.

Круговая диаграмма RFM: доли сегментов по числу клиентов, рядом легенда с долей выручки.

**Приёмка:** графики рисуются при открытии файла с отключённой сетью.

### T1.6 Блок юнит-экономики

Каскад от базового LTV до чистого. Визуально показать, как из выручки вычитаются себестоимость, операционные расходы и привлечение.

Подойдёт горизонтальная полоса, разбитая на сегменты с подписями, либо простая таблица со столбцом «доля от базового LTV».

В частичном режиме нерассчитанные строки выводятся серым с пометкой, чего не хватает.

**Приёмка:** сумма сегментов равна базовому LTV.

### T1.7 Пояснения к метрикам

К каждому блоку подпись на одно-два предложения простым языком: что это за метрика, как её читать, какое значение считается нормальным.

Пример для отношения LTV к CAC: показывает, сколько рублей вкладной маржи приносит клиент на каждый рубль, потраченный на его привлечение. От трёх считается устойчивым, ниже единицы означает, что привлечение не окупается.

Пояснения не всплывающими подсказками, а обычным текстом под блоком. Отчёт должен читаться при печати в PDF.

**Приёмка:** человек без опыта в юнит-экономике понимает, что означает каждая цифра.

### T1.8 Флаг в CLI

`python main.py --html` формирует `output/report.html` рядом с markdown.

`python main.py --html --open` дополнительно открывает файл в браузере.

**Приёмка:** оба формата генерируются из одних данных, цифры совпадают.

## E2. Локальный веб-интерфейс

### T2.1 Приложение

Создать `web/app.py` на Flask. Никаких расчётов внутри, только вызов существующего пайплайна.

Запуск `python web/app.py`, слушает `127.0.0.1:5000`. Наружу не открывается.

**Приёмка:** приложение стартует одной командой, ошибок в консоли нет.

### T2.2 Страница загрузки

Одна страница в стиле дизайн-системы. По центру зона перетаскивания с пунктирной границей.

Принимает CSV и XLSX. При наведении файла граница подсвечивается акцентным цветом.

Под зоной список поддерживаемых колонок и ссылка на пример файла.

**Приёмка:** файл загружается и перетаскиванием, и через выбор по клику.

### T2.3 Валидация до расчёта

После загрузки, до запуска пайплайна, проверить наличие обязательных колонок: дата заказа, идентификатор клиента или контакт, сумма.

Если чего-то нет, показать понятную ошибку с перечнем найденных колонок и тем, что ожидалось. Не отдавать трейсбек.

**Приёмка:** на заведомо неподходящем файле выводится читаемое сообщение, приложение не падает.

### T2.4 Результат

После обработки редирект на страницу с готовым дашбордом. Сверху кнопка скачать HTML.

Временные файлы удаляются после отдачи результата.

**Приёмка:** скачанный файл открывается автономно и идентичен тому, что показан в браузере.

## E3. Тесты

### T3.1 Тест генерации HTML

Проверить, что `report_html` возвращает валидный HTML, содержит все обязательные блоки и не содержит внешних ссылок на CDN.

### T3.2 Тест соответствия форматов

Прогнать один датасет через markdown и HTML, сравнить ключевые числа: базовый LTV, число клиентов, размеры когорт.

### T3.3 Тест частичного режима в HTML

На курсовом файле убедиться, что плашка про неполноту данных присутствует, а нерассчитанные метрики выводятся прочерком, а не нулём.

---

## Чего не делать

Не подключать React, Vue и сборщики. Обычный HTML, CSS и минимум JS.

Не тянуть шрифты и библиотеки из сети. Всё внутри файла.

Не добавлять авторизацию, базу данных и хранение истории отчётов.

Не менять `prepare.py`, `cohorts.py`, `cohorts_sql.py`, `model.py`, `behavior.py`, `rfm.py`. Только чтение их результатов.

Не удалять генерацию markdown. Оба формата сосуществуют.

---

## Порядок

E1 целиком, потом E3, потом E2.

Причина: HTML-файл решает восемьдесят процентов задачи сам по себе. Веб-интерфейс это удобство поверх, и его можно не делать, если руки не дойдут.
