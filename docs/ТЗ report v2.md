# ТЗ: переработка генератора отчёта (report.py v2)

Задача для агентной IDE. Проект `cohort-unit-economics`, Python 3.14, Pandas, SQLite.

---

## Контекст

Инструмент считает когортный анализ и юнит-экономику по выгрузкам заказов. Работает на двух движках, Pandas и SQLite, с проверенным паритетом.

Текущий генератор отчёта `src/report.py` выдаёт результат, который вводит в заблуждение на неполных данных. На курсовых файлах, где нет колонок себестоимости и привлечения, отчёт печатает статус `UNPROFITABLE (Привлечение убыточно, LTV не покрывает CAC)`, валовую маржу 100% и коэффициент LTV/CAC равный `0.0x`.

Причина: `clean_orders_data` заполняет отсутствующие колонки нулями, модель честно считает по нулям, но отчёт не отличает «ноль» от «нет данных».

---

## Что сделать

### 1. Определение полноты данных

Добавить функцию, которая до расчёта модели проверяет входной датафрейм и возвращает словарь доступности полей.

Правило: поле считается отсутствующим, если колонки нет либо сумма по всему датафрейму равна нулю.

Проверяемые поля: `cogs`, `acquisition_cost`, `delivery_cost`, `discount_amount`.

Результат передаётся в генератор отчёта и определяет режим: `full`, если есть и `cogs`, и `acquisition_cost`; иначе `partial`.

### 2. Раздел 0 «Полнота исходных данных»

Первый раздел отчёта после шапки. Таблица из трёх колонок: поле, есть или нет, влияние на расчёт.

Под таблицей текстовая строка про режим расчёта. В режиме `partial` явно перечислить, какие блоки не рассчитаны и почему.

Формулировки нейтральные. Не «ошибка», не «проблема», а «в источнике нет данных о себестоимости, поэтому блок маржинальности не рассчитан».

### 3. Убрать ложный статус

В шапке отчёта не выводить `health_status`, если режим `partial`.

В `src/model.py` функция `build_unit_economics_model` должна принимать словарь доступности и возвращать `None` вместо числа для метрик, которые нельзя посчитать:

- `direct_ltv_1` = None, если нет `cogs`
- `direct_ltv_2` = None, если нет `cogs`
- `net_ltv` = None, если нет `cogs` или `acquisition_cost`
- `ltv_to_cac_ratio` = None, если нет `acquisition_cost` или CAC равен нулю
- `health_status` = None, если `ltv_to_cac_ratio` равен None

В отчёте вместо `None` печатать «не рассчитан» с указанием, чего не хватает.

Существующие тесты на инварианты экономики должны продолжать проходить на синтетике, где данные полные. Добавить проверку, что на курсовых данных возвращается `None`, а не ноль.

### 4. Матрица удержания: различать ноль и отсутствие периода

Сейчас в матрице стоят нули там, где период ещё не наступил. Например, у когорты 2022-01 после M1 идут нули до M8.

Для каждой когорты вычислить максимально доступный период как разницу в месяцах между последней датой в датасете и месяцем когорты.

Ячейки с периодом больше максимально доступного печатать как `—`, а не как `0`.

Ноль оставлять только там, где период наступил и никто не вернулся.

### 5. Средние по столбцам только по заполненным ячейкам

Найти в `src/behavior.py` расчёт среднего удержания и отвала. Проверить, участвуют ли в усреднении ненаступившие периоды.

Если да, исправить: усреднять только по когортам, у которых данный период доступен.

В отчёте под строкой среднего удержания добавить строку «Когорт в расчёте» с количеством.

### 6. Проценты рядом с абсолютными значениями

После абсолютной матрицы вывести вторую матрицу с долей от размера когорты в процентах, один знак после запятой.

Ограничить обе матрицы первыми девятью периодами, M0 по M8, чтобы таблица помещалась по ширине.

### 7. Самопроверка LTV в отчёте

После блока поведения базы добавить строку, где базовый LTV посчитан двумя способами: через произведение среднего чека, частоты и срока жизни, и через прямую сумму выручки на клиента.

Вывести оба числа и расхождение в процентах. Это демонстрация того, что расчёт перепроверяется.

### 8. Блок аномалий

Если в матрице удержания есть отрицательный отвал, то есть в периоде N вернулось больше клиентов, чем в периоде N минус один, вывести подраздел «Аномалии» с перечислением таких когорт и периодов.

Формулировка: «Отрицательный отвал в когорте 2021-03 на M2: вернулось больше клиентов, чем в предыдущем периоде».

### 9. Раздел «Что нужно добавить в выгрузку»

В режиме `partial` в конце блока юнит-экономики вывести список полей, которых не хватает для полного расчёта, с указанием, что именно они разблокируют.

## Критерии приёмки

1. `python main.py --sql --input data/course/sheet_02_15phCO86.csv` формирует отчёт без строки `UNPROFITABLE`.
2. В отчёте по курсовым данным присутствует раздел 0 с пометкой, что нет себестоимости и привлечения.
3. В матрице удержания курсового отчёта у когорты 2022-01 стоят прочерки, а не нули, начиная с M2.
4. `python main.py` на синтетике формирует полный отчёт со всеми метриками и статусом.
5. Все существующие девять тестов проходят.
6. Добавлен тест `test_partial_mode_returns_none`: на курсовом файле `direct_ltv_1`, `net_ltv` и `ltv_to_cac_ratio` равны `None`.
7. Добавлен тест `test_retention_matrix_marks_unavailable_periods`: у последней когорты число заполненных ячеек равно числу доступных периодов.
8. Добавлен тест `test_average_retention_excludes_unavailable`: среднее удержание по периоду M5 считается по меньшему числу когорт, чем по M1.
